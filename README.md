# FieldControl

Веб-платформа для контроля работы торговых представителей и торговых точек. FieldControl объединяет маршруты и GPS-визиты, QR-проверку оборудования, фотоотчёты, задачи сотрудников и панель руководителя.

> **Статус:** демонстрационный MVP для хакатона. Продажи и часть бизнес-показателей используют тестовый набор данных. Интеграция с собственной системой предотвращения кассовых разрывов запланирована и пока не реализована.

## Что умеет прототип

- **Маршруты на день:** для каждого сотрудника хранится отдельный маршрут; можно добавить точку с адресом и временем или убрать её.
- **GPS-визиты:** торговый представитель фиксирует посещение точки. Браузер должен разрешить геолокацию.
- **QR-проверка морозильника:** камера считывает QR-код точки; результат проверки сохраняется на сервере. Если оборудование отсутствует, создаётся инцидент для руководителя.
- **Фотоотчёт:** снимок отправляется на анализ Gemini, если ИИ настроен. В SQLite сохраняются сведения об отчёте и результат анализа, но не исходный файл фотографии.
- **Календарь задач:** сотрудник добавляет задачу, срок и комментарий, затем отмечает выполнение. Руководитель видит общий список задач и статусы.
- **Панель руководителя:** инциденты обновляются из API, доступны аналитика продаж и рекомендации ИИ.

### Демо-аналитика

Данные продаж в `main.py` являются тестовым сценарием, а не данными компании. Показатель падения сравнивает последнюю неделю с соответствующей неделей предыдущего периода. Для суммы за весь шестинедельный период возвращается отдельный показатель `period_drop_pct`. Выполнение плана в демонстрационном наборе — 3 750 000 ₸ из 7 500 000 ₸, то есть 50%.

## Технологии

- Python и Flask

- Gemini API для фотоанализа и ИИ-функций

## Запуск локально

Требуется Python 3.10 или новее.

```powershell
python -m venv .venv
.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
python main.py
```

Откройте:

- `http://localhost:5000` — вход и кабинет торгового представителя
- `http://localhost:5000/dashboard` — та же страница с выбранной ролью руководителя

### Тестовые профили

| Роль | Логин | Пароль |
|---|---|---|
| Торговый представитель | `agent@demo.kz` | `1234` |
| Руководитель | `manager@demo.kz` | `1234` |

Другие демонстрационные профили доступны на странице входа. Регистрация, роли и вход в этом MVP демонстрационные и хранятся на стороне браузера. Перед реальным использованием необходима серверная авторизация и проверка прав доступа на API.

## Настройка Gemini

Создайте `.env` в корне проекта и добавьте:

```dotenv
AI_PROVIDER=gemini
GEMINI_API_KEY=ваш_ключ_Gemini
```

После сохранения перезапустите сервер. Статус провайдера можно посмотреть по адресу `http://localhost:5000/api/ai/status`.

Чат и текстовые рекомендации в `ai_service.py` поддерживают Gemini, OpenAI-совместимые API, Anthropic и YandexGPT. Анализ изображений в текущей версии реализован для Gemini. Без доступного Gemini фотоотчёт сохранится, но результат анализа будет недоступен.

Не добавляйте `.env` с рабочим ключом в GitHub. Храните ключ в локальном файле или настройках окружения.

## Камера и геолокация

Браузеры обычно разрешают камеру и точную геолокацию только на `localhost` или по HTTPS. Для проверки с телефона используйте HTTPS-туннель или настройте HTTPS-сертификат. QR-библиотека загружается с CDN, поэтому для сканирования требуется интернет-соединение.

## Основные API

| Метод | Путь | Назначение |
|---|---|---|
| `GET`, `POST` | `/api/routes` | Получить или добавить маршрутную точку сотрудника на выбранную дату |
| `DELETE` | `/api/routes/<id>` | Убрать точку из маршрута |
| `POST` | `/api/visit/start` | Зафиксировать GPS-визит |
| `GET` | `/api/visits` | Получить историю визитов |
| `POST` | `/api/equipment/verify` | Сохранить результат QR-проверки (`found` или `missing`) |
| `GET` | `/api/equipment/checks` | Получить историю проверок оборудования |
| `POST` | `/api/photo-report` | Отправить фотоотчёт и запросить ИИ-анализ |
| `GET`, `POST` | `/api/tasks` | Получить задачи или создать задачу сотрудника |
| `PATCH` | `/api/tasks/<id>` | Изменить статус своей задачи (`open` или `done`) |
| `GET` | `/api/incidents` | Получить инциденты и показатели дашборда |
| `GET` | `/api/analytics` | Получить тестовые данные и рассчитанные показатели продаж |
| `GET` | `/api/analytics/ai` | Получить рекомендации руководителю |
| `POST` | `/api/chat` | Отправить вопрос ИИ-помощнику |
| `GET` | `/api/health` | Проверить состояние приложения и базы |

Маршрутные API принимают `agent_name` и дату в формате `YYYY-MM-DD`. Для задач сотрудник передаётся как `agent_name`; текущая демо-авторизация не подтверждает личность на сервере.

## База данных

SQLite создаётся автоматически при запуске. По умолчанию файл `milkcontrol.db` находится рядом с `main.py`; расположение можно задать переменной `DB_PATH` в `.env`.

Маршруты и задачи сохраняются в базе и переживают перезапуск сервера. `POST /api/reset` восстанавливает демонстрационные записи кейса; пользовательские маршруты и задачи при этом сохраняются.

## Бизнес-кейс и планы

Проект рассматривается как шестимесячный пилот для 20 торговых представителей и до 500 торговых точек. Предварительная смета команды — 8 500 000 ₸; ставки, объём продаж, рост на 15–30% и сроки окупаемости являются расчётными допущениями и должны быть проверены на пилоте.

Дальнейшие этапы:

1. Подключить реальные данные продаж, остатков и планов из учётных систем.
2. Интегрировать FieldControl с собственной системой предотвращения кассовых разрывов.
3. Проверить точность фотоанализа и KPI на пилотной группе.
4. Добавить серверную авторизацию, разграничение доступа и внешние уведомления.
